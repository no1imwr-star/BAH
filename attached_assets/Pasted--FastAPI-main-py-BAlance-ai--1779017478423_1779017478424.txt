Полностью перепиши концепцию и код FastAPI приложения в main.py. Преврати BAlance.ai в ИИ-Автопилот полного цикла для Бизнес-аналитика. Сервис должен принимать на вход краткое описание задачи текстом и автоматически генерировать полный комплект проектных артефактов.

Выполни следующие технические требования:

1. ИЗМЕНЕНИЕ ИНТЕРФЕЙСА (Airbnb Style)
- Главная страница (`/`): Оставь только одну большую текстовую область (TextArea) с подписью: "Введите краткую бизнес-задачу или идею проекта (например: Автоматизировать складской учет или Запустить мобильное приложение для доставки еды)".
- Кнопка отправки: "Сгенерировать полный комплект проектной документации".
- Дизайн: Светлый, лаконичный, крупные шрифты, мягкие тени у карточек.

2. СТРУКТУРА ВЫДАЧИ АРТЕФАКТОВ НА СТРАНИЦЕ РЕЗУЛЬТАТОВ (`/analyze`)
После анализа текста моделью "llama-3.1-8b-instant", страница должна отображать 4 вкладки (Tabs) с готовыми документами:

- Вкладка 1: "Концепция и Границы (Vision & Scope)"
  * Бизнес-цели и метрики успеха (KPI).
  * Границы проекта (Входит в рамки / НЕ входит в рамки разработки).
  * Глоссарий проекта (Словарь ключевых терминов).

- Вкладка 2: "Спецификация требований (SRS)"
  * Функциональные требования (Что должна делать система).
  * Нефункциональные требования (Безопасность, Производительность, UI/UX).

- Вкладка 3: "Сценарии взаимодействия (Use Cases & Stories)"
  * Роли/Акторы в системе.
  * Развернутый Use Case по Коберну (Предусловия, Основной сценарий, Расширения, Постусловия).
  * Список User Stories для разработчиков в формате: 'Как [Роль], я хочу [Функционал], чтобы [Ценность]'.

- Вкладка 4: "Управление бэклогом (RTM Matrix)"
  * HTML-таблица Матрицы трассировки требований с приоритетами по методологии MoSCoW (Must, Should, Could).

3. ЛОГИКА СИСТЕМНОГО ПРОМПТА ДЛЯ GROQ
- Инструкция для ИИ: "Ты — Lead Business Analyst. Твоя задача — превратить краткую бизнес-идею пользователя в исчерпывающий пакет проектной документации. Выдай ответ строго на русском языке в формате Markdown, разделяя вышеописанные блоки специальными маркерами (например, [SECTION_1], [SECTION_2], [SECTION_3], [SECTION_4]), чтобы Python мог разложить их по вкладкам интерфейса. Будь максимально детален и профессионален."

4. СКАЧИВАНИЕ В ФОРМАТАХ WORD (.DOCX) И PDF
- В файле `requirements.txt` убедись в наличии: python-docx, xhtml2pdf, markdown.
- На странице результатов добавь блок "📥 Экспорт документации:".
- Реализуй эндпоинты `/download/docx` и `/download/pdf`, которые берут полный текст сгенерированных артефактов, конвертируют их "на лету" (из Markdown в форматы Word и PDF) и отдают пользователю в виде скачиваемых файлов. Для PDF укажи системные шрифты (Arial, Helvetica), поддерживающие кириллицу.

Убедись, что код написан чисто, без синтаксических ошибок, обработка исключений корректна. Закоммить код и отправь (push) изменения в GitHub.
