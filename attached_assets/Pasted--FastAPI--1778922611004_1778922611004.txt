Проведи масштабный рефакторинг и редизайн текущего FastAPI приложения. Структуру кода и логику работы с файлами / Groq оставь прежней, но полностью измени позиционирование, UI/UX дизайн и качество генерируемых бизнес-артефактов.

Выполни следующие 4 задачи:

1. ПЕРЕИМЕНОВАНИЕ ПРОДУКТА (Бизнес-аналитический бренд)
- Измени название сайта во всех заголовках, тегах <title> и на экранах.
- Новое название: "BAlance.ai" (с подзаголовком: "CRM Streamlining & Funnel Architecture"). Название обыгрывает роль BA (Business Analyst) и балансировку, наведение порядка в хаосе бизнес-процессов.

2. РЕФАКТОРИНГ ПРОМПТА И СТАНДАРТОВ USE CASE (Взгляд со стороны Senior BA)
- Перепиши системный промпт для модели Groq (llama-3.1-8b-instant). ИИ должен генерировать Use Case строго по профессиональной методологии Алистера Коберна, трансформируя ручные действия пользователя в системные автоматизации.
- Требуй от ИИ выдавать Use Case на русском языке строго по следующей структуре:
  * ID и Название: UC-01: Оптимизация конверсии на этапе Квалификации (или динамически подставляй этап воронки из файла).
  * Контекст / Цель: Выявление коренных причин (Root Cause Analysis) потери сделок на ранних этапах и предиктивное управление воронкой.
  * Главный Актор: Менеджер CRM / Системный триггер.
  * Предусловия: Сделка переведена в статус "Квалификация", система зафиксировала отсутствие активности более X часов.
  * Основной сценарий (Системные шаги):
    1. Система считывает логи изменения статусов сделки из БД.
    2. Система автоматически вычисляет метрику Days_In_Stage и сравнивает её с SLA этапа.
    3. При превышении лимита система инициирует скрипт валидации причин потери (Lost Reason).
    4. Менеджер выбирает формализованную причину из динамического справочника CRM.
    5. Система логирует изменения, пересчитывает общую конверсию воронки и отправляет событие в модуль аналитики.
  * Расширения и альтернативные сценарии: Описать поведение системы, если данные в CRM заполнены некорректно или отсутствует интеграция с телефонией / мессенджерами стейкхолдеров.
  * Постусловия: Статус сделки обновлен в БД, в CRM сгенерирована предиктивная задача на удержание клиента.

3. ПРЕМИАЛЬНЫЙ UI/UX В СТИЛЕ AIRBNB (Редизайн)
- Полностью удали стили water.css. Напиши кастомный, чистый CSS внутри HTML-шаблонов.
- Стиль Airbnb: 
  * Фон страницы: ультра-светлый, чистый (background-color: #f7f7f7 или #ffffff).
  * Цветовая палитра: Основной черный (#222222) для текста, приглушенный серый (#717171) для подзаголовков, акцентный благородный кораллово-красный (#FF385C) для главных кнопок.
  * Компоненты: Крупные скругления углов (border-radius: 12px или 16px), мягкие размытые тени у карточек (box-shadow: 0 6px 16px rgba(0,0,0,0.12)), много свободного пространства (padding и gap), современные шрифты (Geometria, Inter или Segoe UI).
  * Форма загрузки: Сделай её в виде минималистичной красивой карточки по центру экрана с аккуратной иконкой.

4. ИСПРАВЛЕНИЕ БАГА С ЛИНИЯМИ И СТРЕЛКАМИ В BPMN
- Ошибка "no process to display" или пропадающие линии связей возникают из-за некорректного рендеринга пустых контейнеров в bpmn-js.
- В файле main.py обнови `BPMN_BASE_TEMPLATE`. Убедись, что в XML коде шаблона жестко прописаны связи `<bpmn:sequenceFlow>` и соответствующие им графические элементы стрелок `<bpmndi:BPMNEdge>` с точными координатами `di:waypoint`. Вся цепочка от StartEvent через Activity_1 и Activity_2 до Event_1 должна быть непрерывной.
- На странице результатов в блоке скрипта инициализации `BpmnJS` добавь авто-подгонку и центрирование схемы:
  ```javascript
  viewer.importXML(bpmnXML).then(function() {
      var canvas = viewer.get('canvas');
      canvas.zoom('fit-viewport');
      // Добавляем автоматическое выравнивание по центру, чтобы схема не съезжала
      canvas.viewbox({x: 100, y: 0, width: 600, height: 300});
  });
  ```

После внесения изменений сделай автоматический коммит и отправь актуальный код в GitHub репозиторий.
