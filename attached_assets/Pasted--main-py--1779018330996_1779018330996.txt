Проведи глубокий рефакторинг логики генерации и интерфейса в main.py. Нам необходимо структурировать выдачу артефактов под строгие стандарты инженерии требований (BABOK / IEEE 29148) и вернуть визуализацию процессов.

Выполни следующие доработки:

1. ОБНОВЛЕНИЕ СТРУКТУРЫ АРТЕФАКТОВ НА СТРАНИЦЕ РЕЗУЛЬТАТОВ
После анализа идеи пользователя моделью "llama-3.1-8b-instant", интерфейс должен отображать 4 вкладки (Tabs) в премиальном стиле Airbnb:

- Вкладка 1: "Пирамида требований (BR / UR / FR / NFR)"
  Строгое разделение на 4 уровня:
  * Бизнес-требования (Business Requirements): Глобальные цели, метрики (KPI As-Is/To-Be).
  * Пользовательские требования (User Requirements): Роли (Акторы) и их высокоуровневые цели.
  * Функциональные требования (Functional Requirements): Системные фичи, правила валидации, интеграции.
  * Нефункциональные требования (Non-Functional Requirements): Безопасность, производительность, SLA.

- Вкладка 2: "Сценарии (Развернутые Use Cases)"
  * Детальный Use Case по Коберну. Обязательно должен содержать: Предусловия, Постусловия, Основной успешный сценарий (по шагам взаимодействия Актора и Системы).
  * Блок "Расширения и альтернативные сценарии": Минимум 3-4 ветвления на случай неуспешного исхода (например: ошибка валидации, отказ внешней системы, прерывание действия пользователем) с четким описанием реакции системы.

- Вкладка 3: "Стартовый процесс (BPMN Diagram)"
  * Визуальная блок-схема процесса To-Be в синтаксисе Mermaid.js (`graph TD`), отображающая стартовое событие, последовательность задач, логические шлюзы (развилки) и финальные исходы (успех/отказ).
  * На фронтенде контейнер для схемы: `<pre class="mermaid">{bpmn_mermaid}</pre>`. Убедись, что подключена библиотека через CDN: <script type="module">import mermaid from 'https://jsdelivr.net'; mermaid.initialize({ startOnLoad: true, theme: 'neutral' });</script>

- Вкладка 4: "Бэклог и Трассировка (Jira / MoSCoW)"
  * HTML-таблица Матрицы трассировки: ID требования | Описание | Приоритет MoSCoW (Must/Should/Could) | User Story для Jira.

2. МОДИФИКАЦИЯ БЭКЕНДА И ПРОМПТИНГА
- Измени системный промпт для Groq. Требуй разделять сгенерированные блоки специальными текстовыми маркерами (например, [TAB_1], [TAB_2], [TAB_3], [TAB_4]), чтобы Python мог безошибочно распарсить ответ по переменным и разложить по вкладкам.
- Добавь в Python валидацию строки Mermaid: очищай её от маркеров ```mermaid и ``` перед передачей на фронтенд.
- Убедись, что эндпоинты скачивания Word (.docx) и PDF собирают полный текст всех четырех разделов в один документ.
