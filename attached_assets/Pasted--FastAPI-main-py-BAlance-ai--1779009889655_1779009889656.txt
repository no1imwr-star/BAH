Полностью перестрой логику работы FastAPI приложения в main.py. Теперь сервис BAlance.ai должен принимать на вход не таблицы, а готовые файлы бизнес-процессов в формате `.bpmn` (XML) и автоматически конвертировать их в полную проектную документацию бизнес-аналитика.

Реализуй следующие изменения:

1. ИЗМЕНЕНИЕ ИНТЕРФЕЙСА (Airbnb Style)
- На главной странице измени форму загрузки: теперь она должна принимать строго файлы с расширением `.bpmn`.
- Подпись к форме: "Загрузите вашу схему в формате .bpmn для автоматической генерации спецификации требований и бэклога".
- Текстовое поле TextArea оставь необязательным (для ввода дополнительных бизнес-целей проекта).

2. БЭКЕНД: ПАРСИНГ BPMN XML НА PYTHON
- В функции `/analyze` реализуй чтение файла .bpmn как текстового XML-документа. Перед чтением обязательно делай `file.file.seek(0)`.
- Напиши базовый парсер строк (или используй xml.etree.ElementTree), который извлекает из файла:
  * Названия всех задач (все текстовые атрибуты name внутри тегов bpmn:userTask, bpmn:serviceTask, bpmn:task).
  * Названия участников/ролей (атрибуты name в тегах bpmn:participant или bpmn:lane).
  * Название самого процесса (атрибут name в теге bpmn:process).
- Сформируй из этих данных сжатый текстовый контекст: список найденных шагов процесса и список акторов.

3. ОБНОВЛЕНИЕ СИСТЕМНОГО ПРОМПТА ДЛЯ GROQ (Генерация Enterprise-спеки)
- Передай извлеченные шаги процесса и роли в модель "llama-3.1-8b-instant". 
- Системный промпт для ИИ должен звучать так:
  "Ты — Senior Business/System Analyst. Тебе предоставлена структура бизнес-процесса, извлеченная из файла BPMN. Твоя задача — декомпозировать этот визуальный процесс в текстовую проектную документацию. Выдай ответ на русском языке строго в формате Markdown, разделенный на три раздела:
  
  РАЗДЕЛ 1: ПОЛНАЯ СПЕЦИФИКАЦИЯ ТРЕБОВАНИЙ (Requirements Specification)
  - Бизнес-требования (BR): Бизнес-цели автоматизации данного процесса и метрики успеха.
  - Пользовательские требования (UR): Подробный Use Case по Коберну на основе шагов из BPMN (Предусловия, Основной сценарий взаимодействия Актора и Системы по шагам, Расширения, Постусловия).
  - Функциональные требования (FR): Что должна делать система для реализации каждого шага из BPMN (валидации, интеграции, триггеры).
  - Нефункциональные требования (NFR): Требования к безопасности, производительности и интерфейсу.

  РАЗДЕЛ 2: МАТРИЦА ПРИОРИТИЗАЦИИ И ТРАССИРОВКИ (MoSCoW Matrix)
  - Сгенерируй HTML-таблицу: ID требования | Описание функциональной фичи | Приоритет по методологии MoSCoW (Must, Should, Could). Свяжи требования с шагами исходного BPMN.

  РАЗДЕЛ 3: ЭКСПОРТ БЭКЛОГА ДЛЯ JIRA (User Stories)
  - Сгенерируй готовый список User Stories для разработчиков в формате: 'Как [Роль из BPMN], я хочу [Функционал], чтобы [Бизнес-ценность]'. Добавь к каждой истории краткие критерии приемки (Acceptance Criteria)."

4. СТРАНИЦА РЕЗУЛЬТАТОВ И СКАЧИВАНИЕ
- На странице результатов красиво отобрази сгенерированные разделы документации.
- Выведи блок "Статистика BPMN": покажи пользователю количество обнаруженных шагов и участников в его файле.
- Реализуй функционал скачивания: добавь кнопку "Скачать спецификацию (.md)", которая позволяет пользователю сохранить весь сгенерированный текст в виде готового файла требований.

Убедись, что код не содержит синтаксических ошибок, обработка исключений (try-except) работает корректно, а дизайн в светлых тонах Airbnb аккуратно форматирует таблицы и списки. Сделай коммит и отправь изменения в GitHub.
